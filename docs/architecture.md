# 架构设计：视频号剧目挂载分佣 AI 自运营团队

## 1. 总体分层

```
┌─────────────────────────────────────────────────────────┐
│  可视化工作台 (frontend/index.html, 4s 轮询实时刷新)        │
│  KPI总览 · 团队实时状态 · 每日流程流水线 · 九大业务页签      │
├─────────────────────────────────────────────────────────┤
│  服务层 FastAPI (backend/api/app.py)                      │
│  /api/overview /api/ledger /api/reports /api/contents…   │
│  手动触发: 巡检 / 整日流程 / 内容发布 / CSV数据导入          │
├─────────────────────────────────────────────────────────┤
│  编排层 (backend/pipeline/)                               │
│  Scheduler: 30min巡检 · 每日9:00自运行流程                  │
│  DailyFlow: 日报→早会→拆解→内容→预案→复盘→经验入库          │
├─────────────────────────────────────────────────────────┤
│  Agent层 (backend/agents/)                                │
│  主管 · 全网对标专员 · 爆款拆解专员 · 内容生成 · 策略迭代    │
│  统一基类: 运行日志 / 告警广播 / 经验入库 / LLM叙事         │
├─────────────────────────────────────────────────────────┤
│  采集层 (backend/collectors/)                             │
│  PeerCollector 标准接口                                    │
│  ├─ MockCollector      模拟源(默认, 跑通全流程)             │
│  └─ ThirdPartyCollector 第三方数据平台API(合规生产源)       │
├─────────────────────────────────────────────────────────┤
│  数据层 SQLite (backend/db.py, WAL模式)                    │
│  14张表: 剧目/同行/台账/72h快照/自有作品/分成/拆解/内容/     │
│         策略/经验库/早会/告警/运行日志/日报                 │
└─────────────────────────────────────────────────────────┘
```

## 2. 五角色职责与系统映射

| 角色 | 模块 | 核心动作 | 产出物 |
|---|---|---|---|
| 主管 | `supervisor.py` | 早会统筹、任务分配、分成异常/规则变动第一时间全员同步、每周经验库沉淀清理 | 早会纪要、全员同步告警、经验库周更 |
| 全网对标专员 | `benchmark.py` | 30min 巡检关键词+同行账号、违规自动过滤、台账入库、72h 跨天追踪（D1/D2/D3 快照）、滞后爆款挖掘（首日<2w 且三日≥4倍）、差异化钩子/独家剧目告警 | 对标台账、对标日报、起量规律经验 |
| 爆款拆解专员 | `deconstruct.py` | 拉取自有爆款 → 绑定剧目段落（钩子/冲突/反转/挂载）→ 对比账号均值找起量因子 → 用同行同钩子数据交叉验证 | 拆解报告、高转化结构经验 |
| 内容生成专员 | `content.py` | 按拆解结论+高分历史模板，为在推剧目产出脚本/画面提示词/标题/发布时段（每剧每日≤2条）；发布即登记自有作品并生成分成数据供复盘 | 待审内容队列 |
| 策略迭代专员 | `strategy.py` | 新剧前置策划（用同行同款作品数据判定适配度）、每周回溯淘汰低效策略（低于中位线40%） | 新剧预案、策略淘汰记录 |

## 3. 每日自运行流程（DailyFlow）

```
09:00 触发
 1. 对标日报+跨天复盘   benchmark.daily_report()
 2. 主管早会·同步异动   supervisor.morning_meeting()   ← 消费日报+告警+分成环比
 3. 自有爆款拆解       deconstruct.run()              ← 消费对标结论
 4. 当日内容产出       content.run()                  ← 消费拆解结论+经验模板
 5. 新剧预案更新       strategy.plan_new_dramas()
 6. 发布分成复盘       revenue_review()                ← 分成环比>20%记为有效经验
 7. 有效经验入库       supervisor.weekly_experience_review()
```

独立调度：每 30 分钟 `patrol()`（巡检入库+规则巡检）+ `track()`（72h 快照补全）。

## 4. 关键设计决策

**数据唯一决策依据**：所有 Agent 结论均由 SQLite 中真实分成/播放/转化数据驱动（阈值判定、均值对比、环比计算），LLM 仅负责叙事润色——未配置 LLM 时系统用模板生成，结论不失效。

**采集合规**：视频号无公开 API，爬虫有封号和协议风险。系统以 `PeerCollector` 接口隔离采集实现，生产路径为授权第三方数据平台 API（`ThirdPartyCollector`）；自有账号数据走后台 CSV 导出 + `/api/import/share_records` 导入。默认 `MockCollector` 保证开箱即跑。

**滞后爆款识别**：`is_late_boom = 首日播放<2万 且 第三日/首日≥4倍`，命中即告警 + 提炼经验入库，供内容专员复用结构。

**策略淘汰闭环**：`weekly_review()` 按近 7 日分成排名，低于中位线 40% 的策略标记「已淘汰」并反向入库经验，防止同类剧目复用低效打法。

**并发与容错**：单 SQLite 连接 + WAL + 写锁；调度作业独立线程、单点异常只记录 `agent_runs(status=error)` 不中断调度循环；`pipeline_running` 标志防止流程重入。

## 5. 扩展点

- **LLM 接入**：配置 `LLM_BASE/LLM_KEY/LLM_MODEL`（OpenAI 兼容），各 Agent 叙事自动切换为模型生成
- **巡检范围**：`WATCH_KEYWORDS` / `WATCH_ACCOUNTS` 环境变量热配置
- **新数据源**：实现 `PeerCollector` 三方法即可接入任意授权数据源
- **审批流**：内容发布当前为工作台一键确认；如需全自动，将 `content.publish` 挂入 DailyFlow 第 4 步之后即可
